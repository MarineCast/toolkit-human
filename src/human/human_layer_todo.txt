Reporting-Opportunity Proxy
---------------------------

- [x] Build land and water reporting-opportunity components separately.
- [ ] Combine static viewshed support with source activity, weather, daylight,
      calendar, access, and source-coverage evidence.
- [ ] Publish a reporting-opportunity index without presenting it as true whale
      presence or guaranteed detection probability.
- [ ] Calibrate P_REPORTING_OPPORTUNITY only within public independent-detection
      support; leave it null outside calibration support.
- [ ] Publish uncertainty, calibration scope, measurement status, and source
      availability beside the probability.
- [x] Prevent reporting adoption, sightings, viewing events, and held-out whale
      outcomes from entering the proxy.

Negative Vessel-Pressure Proxy
------------------------------

- [ ] Deduplicate ferry vessels from AIS using explicit MMSI/vessel mappings
      before adding route-derived ferry activity.
- [ ] Publish total and class-specific vessel-hours, vessel-kilometres, speed
      bands, ferry pressure, jurisdiction coverage, and measurement status.
- [ ] Define the general proxy as:

      VESSEL_PRESSURE_INDEX =
          0.5 * scaled_log_vessel_hours
        + 0.5 * scaled_log_vessel_km

- [ ] Calculate each scaled component with log1p, cap it at a manifest-pinned
      q99, and scale it using the first 104 consecutive coverage-complete weeks.
- [ ] Publish NEGATIVE_VESSEL_PRESSURE = -VESSEL_PRESSURE_INDEX.
- [ ] Leave the general index unavailable when required AIS coverage or ferry
      deduplication is incomplete; a separate ferry proxy may remain partial.
- [ ] Retain speed and vessel-class components separately instead of inventing
      acoustic source-level weights.
- [ ] Treat the proxy as vessel-activity pressure, not measured noise exposure
      or a demonstrated causal effect on whale presence.

SRKW and Transient Evaluation
-----------------------------

- [ ] Evaluate SRKW first using identical origins, cells, labels, support, and
      as-of contracts across all comparison arms.
- [ ] Compare baseline, baseline plus reporting opportunity, baseline plus
      vessel pressure, and baseline plus both proxies.
- [ ] Use only lagged observed vessel pressure in forecast experiments.
- [ ] Allow contemporaneous vessel activity only in a separately labeled
      retrospective association analysis.
- [ ] Add future vessel activity as a negative control and run source-dropout
      and coverage-sensitivity tests.
- [ ] Report Brier score, log loss, calibration, top-k recall, spatial
      residuals, uncertainty, and origin-level stability.
- [ ] Describe vessel-pressure results as associations with reported whale use,
      not causal presence effects.
- [ ] Consider future promotion only if the supported association is
      consistently nonpositive across rolling origins and improves held-out
      performance without degrading calibration.
- [ ] After SRKW validation, repeat the unchanged contract for Transients and
      report ecotype-specific results separately.
